# Running notes benchmark (synthetic)

Generated by `benchmarks/running_notes_bench.py` with ctxfit 0.6.0. **All transcripts are synthetic** (seeded random generators shaped like agent runs: source files, test logs and JSON API responses for the coding agent; web pages and search results for the research agent). The summariser is a **fake** that returns a fixed 1,200-char digest, so notes quality is not measured at all.

Method: each transcript is replayed one turn at a time; every turn is one request carrying the full history so far, and state is carried between requests like a real agent loop. Default config (keep 4 turns, chunk 4, mask outputs >= 400 chars, notes high water 60k / low water 30k est. tokens). Token figures are ctxfit's chars/4 estimate, summed over all requests of a run, not tokenizer counts. Requests get simulated timestamps (seeded): mostly 10-60 s apart, with a 12% chance of a 6-20 minute pause before a request; ctxfit is told the time, so its cold-cache rules (`cache_ttl_seconds` 300) see the same pauses.

- **sent** = estimated input tokens actually sent, summed over requests (baseline = no rewriting).
- **net saved** = (baseline − sent − summariser in/out) / baseline.
- **cache-stable** = share of requests (after the first) whose output starts with the previous request's output byte for byte (so a provider prompt cache can be reused). The baseline is 100% by construction: without rewriting, every request extends the last.
- **cache-priced cost** = input cost with Anthropic-style prompt caching, as a share of the baseline's cache-priced cost: per request, the leading messages identical to the previous request's are read from cache at 0.1x, the rest is written at 1.25x; summariser input counts 1x and its output 5x. After a pause longer than 300 s the cache has expired: the whole request is written at 1.25x, for every strategy including the baseline. The baseline itself benefits from caching (every request extends the last), so this is the fair comparison. **same, no pauses** = the same cost with every gap 10-60 s (the cache never expires), as a share of the baseline under those conditions.
- **facts visible** = share of the distinct fact tokens (paths, URLs, error codes, versions, ids; the same tokenizer ctxfit uses for `keeps:`) found anywhere in the tool outputs that still appear verbatim in the last request. A crude proxy for 'can the model still see the specifics'; it says nothing about prose content.
- **last request** = estimated tokens of the final request of a transcript, averaged over the transcripts of the corpus.
- **re-reads of hidden output** = times the agent re-ran an identical tool call whose latest earlier output was hidden, squeezed or summarised away in the prompt it had just seen (an older copy being hidden does not count if a newer one was visible). The transcripts are fixed, so this counts *opportunities* for a costly re-fetch, not re-fetches caused by ctxfit; a real agent may or may not re-run the call (or use `ctxfit_recall`).

## Reading this honestly

- **What saves real money with caching:** lossless arrival compaction. It changes each output once, when it first arrives (before anything is cached), so every request still extends the last one (cache-stable 100%) and every fact stays visible. Here it cost 77-79% (coding) and 52-53% (research) of the baseline. Most of that is exact duplicates: these agents re-read the same files and pages, which real agents do too, but your mileage depends on how often yours does.
- **Masking pays mostly through pauses.** With pauses, hide masking cost 65-76%; with the cache always warm, 92-98% (each boundary move rewrites the prefix at 1.25x, which eats most of what it saves). Adding arrival and `clear_at_least_chars` 20k is the cheapest setup here: 51-57% with pauses, 73-74% without.
- **Cold-cache moments help a little.** Moving held-back boundaries during a pause (free, the cache is gone anyway) lowered `clear_at_least_chars` 20k from 64% to 56% (coding) and 74% to 72% (research). With `clear_at_least_chars` 0 it changes nothing, since every move already happens.
- **Notes cost money.** At these low thresholds notes cost 75-93% with pauses and 116-138% without: more than doing nothing. With the default high water (60k) they never engaged. Use notes to stay under a context limit, not to save money.
- **Squeeze** keeps more of each output, so it saves less and, with a warm cache, can cost more than the baseline (116% on research).
- `keeps:` facts cost 1-2 points and keep far more specifics visible; `clear_at_least_chars: auto` behaves like 0 here (these moves are big enough).
- The coding transcripts' JSON rows have a list field, so they never become tables; the research corpus has no tables either. Tables are not what drives these numbers.
- Nothing here measures answer quality. JetBrains Research (Dec 2025) is the evidence we rely on for quality; this script only checks the mechanics.
