# Running notes benchmark (synthetic)

Generated by `benchmarks/running_notes_bench.py` with ctxfit 0.5.0. **All transcripts are synthetic** (seeded random generators shaped like agent runs: source files, test logs and JSON API responses for the coding agent; web pages and search results for the research agent). The summariser is a **fake** that returns a fixed 1,200-char digest, so notes quality is not measured at all.

Method: each transcript is replayed one turn at a time; every turn is one request carrying the full history so far, and state is carried between requests like a real agent loop. Default config (keep 4 turns, chunk 4, mask outputs >= 400 chars, notes high water 60k / low water 30k est. tokens). Token figures are ctxfit's chars/4 estimate, summed over all requests of a run, not tokenizer counts.

- **sent** = estimated input tokens actually sent, summed over requests (baseline = no rewriting).
- **net saved** = (baseline − sent − summariser in/out) / baseline.
- **cache-stable** = share of requests (after the first) whose output starts with the previous request's output byte for byte (so a provider prompt cache can be reused). The baseline is 100% by construction: without rewriting, every request extends the last.
- **cache-priced cost** = input cost with Anthropic-style prompt caching, as a share of the baseline's cache-priced cost: per request, the leading messages identical to the previous request's are read from cache at 0.1x, the rest is written at 1.25x; summariser input counts 1x and its output 5x. The baseline itself benefits from caching here (every request extends the last), so this is the fair comparison.
- **facts visible** = share of the distinct fact tokens (paths, URLs, error codes, versions, ids; the same tokenizer ctxfit uses for `keeps:`) found anywhere in the tool outputs that still appear verbatim in the last request. A crude proxy for 'can the model still see the specifics'; it says nothing about prose content.
- **last request** = estimated tokens of the final request of a transcript, averaged over the transcripts of the corpus.
- **re-reads of hidden output** = times the agent re-ran an identical tool call whose latest earlier output was hidden, squeezed or summarised away in the prompt it had just seen (an older copy being hidden does not count if a newer one was visible). The transcripts are fixed, so this counts *opportunities* for a costly re-fetch, not re-fetches caused by ctxfit; a real agent may or may not re-run the call (or use `ctxfit_recall`).

## Reading this honestly

- Savings depend almost entirely on how much of the history is old tool output. These synthetic transcripts are tool-heavy on purpose; chat-heavy conversations save far less.
- `cache-stable` below 100% means some requests rewrite earlier content and pay a fresh cache write; the chunked boundary keeps those moves rare, `clear_at_least_chars` makes them rarer.
- With the default high water (60k est. tokens) notes never engage on these transcripts: masking alone keeps every request under it. The 8k/4k rows lower the marks only to show the notes mechanics at this scale; each summariser call costs its input (the evicted turns) and that cost is subtracted in `net saved`.
- Priced with prompt caching, the picture is much less rosy than raw tokens: the baseline already reads most of each request from cache at 0.1x, while every boundary move rewrites the prefix and pays 1.25x on it again. Hide masking comes out 2-8% cheaper and `clear_at_least_chars` 20k 7-19% cheaper; squeeze (bigger digests rewritten each move) can cost more than the baseline, and notes at these low thresholds come out MORE expensive than doing nothing (summariser spend plus extra cache writes). Use notes for context limits, not to save money on cached Claude traffic.
- `clear_at_least_chars: auto` behaves like the default here: with Anthropic's prices and 4 expected reuses it only holds moves that hide less than about a third of the prefix, and these transcripts' moves are bigger than that.
- `keeps:` facts on the markers cost a few percent of the savings and keep far more specifics visible (compare the keep_facts off row).
- The JSON API rows in these transcripts have a list field (`tags`), so they are not flat and never become lossless tables; the tables row equals plain squeeze here.
- Squeeze keeps more of each output (head/tail, error lines, JSON shape) so it saves less than hide; whether that avoids re-reads is not something a replay can show.
- Nothing here measures answer quality. JetBrains Research (Dec 2025) is the evidence we rely on for quality; this script only checks the mechanics.
